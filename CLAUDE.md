# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

tbkit builds and solves 1D, 2D and 3D Tight-Binding models in vectorized NumPy/SciPy: finite real-space lattices (flakes, ribbons, disorder, defects, magnetic fields, strain) and periodic Bloch Hamiltonians (band structures, Berry curvature, Chern numbers, spin-orbit coupling, ribbons for edge states). Hermitian and non-Hermitian Hamiltonians are both supported. It targets teaching as much as research, so the mechanics are kept explicit and inspectable.

## Commands

```bash
pip install -e ".[test]"          # tests
pip install -e ".[docs]"          # docs (sphinx, pydata-sphinx-theme, sphinx-gallery)

pytest tests/                                        # full suite, in parallel (pytest-xdist, set in pyproject addopts)
pytest tests/ --cov=tbkit --cov-report=term-missing  # what CI runs (Python 3.10-3.14)
pytest tests/test_kspace.py::test_name -q -n0        # a single test, without worker startup

python examples/<section>/plot_<name>.py             # run one gallery example
cd docs && make html                                 # re-executes every examples/*/plot_*.py; output in docs/build/html
```

- `pyproject.toml` sets `filterwarnings = ["error"]`. Any warning fails the suite. A warning from tbkit is treated as a defect (for example, complex energies reaching matplotlib). Only add a targeted `ignore::` for dependency warnings outside our control.
- The suite has 100% line coverage of `tbkit` (published report linked from the README). New code needs tests that keep it there.
- `tests/conftest.py` forces the matplotlib `Agg` backend.
- CI also runs the suite on the oldest NumPy, SciPy and matplotlib that `pyproject.toml` allows (job `test-minimum-versions`, Python 3.10). Don't use NumPy 2-only APIs (`np.trapezoid`, `import numpy.char`): use `scipy.integrate.trapezoid` and `np.char`.
- Ruff lints `tbkit/` (rules in `pyproject.toml`, CI job `lint`: `ruff check tbkit`). No formatter is configured. mypy runs in CI as an advisory job (`typecheck`, `continue-on-error`) until the existing hints pass.
- CI job `docs` builds the docs (re-running every gallery example) and runs `paper/listings/*.py`.
- `paper/` holds the SciPost Physics Codebases manuscript and everything behind it (Kwant/PythTB cross-checks, benchmarks, figures); see `paper/README.md`. Its scripts need Kwant and PythTB (`paper/environment.yml`), so they are not part of CI, except the listings.
- The default branch is `master`.

## Architecture

There are two independent pipelines. Both start from a `Lattice`:

- **Real space.** `Lattice(unit_cell, prim_vec)` → `get_lattice(n1, n2, n3)` fills `lat.coor`, a NumPy structured array with dtype `[('x','f8'), ('y','f8'), ('tag','U1')]` (plus `('z','f8')` for 3D positions; `lat.space_dim` says which). Geometry edits (`remove_sites`, `ellipse_in`, `boundary_line`, `rotation`, ...) mutate that array in place.
  - `System(lat)` then computes pairwise distances. `set_hopping` addresses bonds by neighbour order `n` (1st, 2nd, ...), optionally narrowed by angle or sublattice-pair tag. It stores them in `sys.hop`, a structured array with fields including `i`, `j`, `t`, `ang` and `tag`.
  - Modifiers act on `sys.hop`/`sys.onsite` and must run *after* `set_hopping`/`set_hopping_manual`: disorder, dimerization, defects, `set_peierls_phase`, `set_magnetic_field`.
  - `get_ham()` builds a sparse CSR matrix. It stores only one triangle of hoppings and adds the conjugate transpose, unless the bond angles mix signs.
  - Value functions: `set_hopping`/`set_onsite` accept callables `t(site_i, site_j, **params)`/`onsite(site, **params)` (helpers in `values.py`). Their rows of `sys.hop` hold the factor `t = 1`, and `sys._hop_values` keeps `(directed bond keys, function)`, so filtering or concatenating `hop` never desyncs them. `get_ham(**params)` multiplies the values in (so later modifiers compose), and assigning a number to the same bonds (`_assign_hopping`) drops the function. `HOP_DTYPE` is unchanged because `io.py` persists it.
  - Above `System.dense_max` (5000) sites, `get_distances` uses a k-d tree instead of the dense N² distance matrix.
  - `System(lat, periodic=True | (bool, ...))` wraps the `n1 a1 x n2 a2 (x n3 a3)` box of `get_lattice` into a torus or cylinder. Every bond displacement goes through `System._min_image` (via `_bond_vectors`): dense distances (row blocks), the k-d tree (`_near_pairs`, images of the sites), `_angles`, `set_hopping_manual`, `set_peierls_phase` (end of the short bond) and the `OrbitalSystem` bond blocks. Use `_bond_vectors(i, j)`, never `coords[j] - coords[i]`, for new bond-vector code. `get_bonds` refuses an order reaching half-way around the torus (`error_handling.torus_size`). `set_magnetic_field` and `get_local_chern_marker` need open boundaries; `get_bott_index` needs a 2D torus. `io` writes `periodic` (archive version 2) only for periodic Systems.
  - `get_eig()` diagonalizes densely with `scipy.linalg`. It can also compute left eigenvectors for non-Hermitian cases. `get_eig_sparse` uses shift-invert. `get_green`, `get_ldos`, `get_fermi_level`/`get_occupations` (via `occupation.py`) and `get_local_chern_marker` build on it.
  - `Plot(sys)`, `Propagation(lat)` (Crank-Nicolson wavepackets and pumping) and `Save` consume the result. `graphene.py` subclasses `Lattice`/`System` with graphene-specific shapes, triaxial strain and the spectrum-versus-strain "butterfly".
- **Reciprocal space.** `KSpace(lat, spin=False)` uses only `unit_cell` and `prim_vec`, never `get_lattice`.
  - Hoppings are given as `{'i', 'j', 'R', 't'}`: an intra-cell orbital pair plus a lattice-vector offset `R`.
  - `get_ham(k)` returns the Bloch matrix. `k_path`, `mesh_grid`, `berry_curvature` and `chern_number` (Fukui-Hatsugai-Suzuki) build on it.
  - Every Bloch matrix (`get_ham`, `get_overlap`, `get_ham_peierls`, `_bloch_derivatives`, `floquet._bloch_grid`) comes from the one vectorized `KSpace._bloch_sum` (many k at once, optional derivatives, `positions`, vector potential `A`). Build new ones through it (or `_bloch_ham`), not with another loop over `_hop`.
  - Every diagonalization over many k-points goes through `KSpace._eigs` (`_subspaces` for band projectors): `_hams` (one Bloch sum, or per-k `get_ham` when a subclass overrides it) and stacked `numpy.linalg` solvers in chunks of `400000 // norb**2` k-points, threaded when `set_workers(n > 1)`. Use it rather than a loop over k-points. `tests/benchmark_kspace.py` times these paths.
  - With `spin=True`, onsite and hopping values may be 2x2 matrices, using `kspace.PAULI`.
  - `KSpace._hop` is a property: the numeric hoppings (`_hop_const`) plus the value functions (`_hop_values`) evaluated with `ks.params` (`set_params`). Assigning it replaces both, so other modules (`bdg`, `moire`, `io`) keep reading and writing `_hop` unchanged. `get_ham(k, **params)` overrides `params` for one call via `_bloch_ham(..., params=)`.
  - `kspace.ribbon(lat, list_hop, width, direction)` returns a new 1D `KSpace` that is finite across the ribbon.
  - `surface_spectral_function(ks, energies, direction, side, eta, bulk)` gives the spectral function of the outermost (or a bulk) cell of the crystal, semi-infinite along `prim_vec[direction]`. It groups cells into principal layers as wide as the longest hopping along that vector, then decimates them with `transport._green_surface_bulk`. That helper is shared with `transport.surface_green`: it regroups 1-3 layers per energy for conditioning, balances non-reciprocal couplings, and runs the vectorized `_decimation`.
  - The Bloch convention is the periodic gauge (orbital positions ignored). The Wilson-loop tools (`berry_phase`, `wannier_centers`, `wannier_flow`, `z2_invariant`) add the positions back with `positions=True`.
  - `set_hopping(..., hermitian=False)` stores a hopping without its conjugate. `finite_ham`, `spectral_winding` and `gbz` serve the non-Hermitian case. `set_overlap` turns every eigenproblem into a generalized one.
  - Non-Hermitian band topology in 2D: `biorthogonal_berry_curvature`/`biorthogonal_chern_number` (LR, RL, RR, LL; real or imaginary line gap). `berry_curvature`/`chern_number` label bands by Re E and raise a ValueError for a non-Hermitian band group without a real line gap (checks `error_handling.line_gap` and `band_continuity`). The Hermitian path is untouched. `tbkit.exceptional` takes a 2D `KSpace` or any callable `H(p)` and a closed loop (`circle`, polygon vertices, or a callable of s in [0, 1]). It follows eigenvalues by continuation (`_track`: linear prediction, Hungarian matching, halving ambiguous steps, never sorting) for `vorticity`, `track_eigenvalues` and `encircle` (midpoint biorthogonal parallel transport). `discriminant` comes from the Sylvester resultant of the characteristic polynomial (no eigenvalues), which feeds `discriminant_winding` and `find_exceptional_points` (plaquette windings on a shifted mesh, Newton refinement, charges, Petermann-based orders, exceptional lines when Delta is real) and `fermi_arcs`. Sign conventions: W = -2 sum nu.
  - `kspace.magnetic_supercell` (rational flux), `slater_koster.sk_kspace` (multi-orbital), `bdg.bdg_kspace` (holes as extra orbitals) and `floquet.FloquetKSpace` (a dynamic subclass whose `get_ham` is the Floquet Hamiltonian) all return `KSpace` objects, so every band and topology tool applies to them.
  - `floquet.DrivenKSpace` is the base of those driven models: a copy of a `KSpace` whose `get_ham` is `H_F(k)` for any `H(k, t)` (branch cut `epsilon`). `floquet.step_drive` builds exact piecewise-constant drives from `KSpace` models or ribbons (a `DrivenKSpace`) or from `System`s/matrices (a real-space `StepDrive`). `DrivenKSpace.winding_number` (Rudner et al. 2013, spectral k-derivatives, returns the raw value) and `edge_state_count` (ribbons) detect anomalous Floquet phases that the Chern numbers of `H_F` miss.
  - `hall_conductivity` and `spin_hall_conductivity` evaluate the Kubo formula over a mesh at any Fermi level (vectorized `_bloch_derivatives`, analytic `dH/dk` from the hoppings; `positions=True` uses bond vectors `R + tau_j - tau_i`). In a gap they equal `chern_number` (TKNN sign, the negative of the Ohm's-law `sigma_xy`). `orbital_magnetization`, `anomalous_nernst_conductivity` and `thermal_hall_conductivity` reuse the same `_hall`/`_kubo` path with other pair weights (`kspace._response_weights`), so add new Berry-curvature responses there. `axion_angle` integrates the second Chern form along a value-function parameter (`_bloch_derivatives(..., params=)`, central difference in the parameter). `finite_velocity` gives `i[H, r]` from bond vectors for `kpm.hall_conductivity` (Kubo-Bastin) on a torus.
- **Other modules.** `orbital.OrbitalSystem` handles multi-orbital, spinful real-space models. `transport.Transport` stores the device sparse (`ham` is a lazily built dense property). `smatrix`, `wave_function`, `ldos` and the default `transmission` (`eta=None`) share `Transport._scattering`: exact lead modes from `_lead_modes` (QZ on the transfer-matrix pencil, `ordqz` Schur basis for the evanescent modes, unit-current propagating modes) and one `splu` of the device plus the lead boundary conditions (Groth et al. 2014). A lead's `conservation_law` (stored in `Transport._laws` as eigenspace bases from `_law_blocks`, so `self.leads` keeps its 4-tuples) makes `_lead_modes` solve each block separately; `SMatrix` addresses `(lead, block)`. `conductance`/`thermoelectric` and `temperature` in `conductance_matrix` integrate over `_fermi_window` (uniform trapezoid in (E - mu)/T, |x| <= 36). The other methods (and `transmission` with an `eta`, non-Hermitian leads or `lead_in == lead_out`) use the dense Caroli formula with Sancho-Rubio leads. `kpm.py` implements the kernel polynomial method. `meanfield.hubbard_mean_field` solves the Hubbard model by linear mixing (`hubbard_mean_field_noncollinear` for spin textures), and `bdg.s_wave_gap` solves the BdG gap equation self-consistently. `transport.RecursiveTransport` handles long quasi-1D devices slice by slice. `optics.py` holds linear and nonlinear optical response, `higher_order.py` nested Wilson loops and corner charges, `moire.py` supercells, band unfolding and twisted bilayers, `topology.py` the Bott index, the finite-sample entanglement spectrum and `find_weyl_points` (gap minima, Newton on the two-band d-vector, sphere-flux chiralities), and `wannier.py` the maximally localized Wannier functions of a band group (`wannierize`: projection with Lowdin orthogonalization, then conjugate-gradient Marzari-Vanderbilt minimization over the overlaps `M(k, b)` between mesh neighbours, which include the orbital positions as the Wilson loops do; functions ordered like the rows of `finite_ham(nk)`). With more bands than trial orbitals (or a `window`/`frozen` window), `_disentangle` first selects the subspace (Souza-Marzari-Vanderbilt: top eigenvectors of `Z(k)` per k, frozen states pinned above and excluded ones below by a diagonal shift, so one stacked `eigh` handles every k). `WannierFunctions.kspace` Fourier-transforms `ham_k` onto Wigner-Seitz images and builds the `KSpace` with `io._hr_kspace`, shared with `read_wannier90`. The sector, spin and mirror Chern numbers share `KSpace._sector_cherns`, which reuses the FHS plaquette product `KSpace._flux`.
- **Model building and I/O.** `KSpace.set_hopping` also accepts the neighbour-order selectors of `System.set_hopping` (bonds found by `neighbours.py`). `bridges.py` converts between `System` and `KSpace` models. `continuum.py` discretizes a k·p Hamiltonian (sympy, polynomial in `k_x, k_y, k_z`) into a `KSpace` on a chain/square/cubic grid; sympy is an optional dependency imported inside the functions (extra `continuum`, also in `test` and `docs`), so `import tbkit` must not import it. Its parametrized onsite terms are appended directly to `_hop_values` as an `i -> i`, `R = 0` bond with `hermitian=False`, since `set_hopping` refuses that bond. `io.py` saves and loads models (versioned `.npz`, no pickle) and reads Wannier90 files.
- **Shared helpers.** `dos.density_of_states` is used by both `System` and `KSpace` plotting. `lattices.py` returns ready-made `Lattice` objects (chain, square, triangular, honeycomb, kagome, Lieb).
  - `dos._mesh_simplices`/`_simplex_values` split a periodic k-mesh into d! simplices per cell (segments, triangles, tetrahedra along the main diagonal). Both `dos.tetrahedron_dos` (exact integration of the linear interpolation) and `kspace._level_set` (marching triangles/tetrahedra behind `KSpace.fermi_surface` and `plot_spin_texture`) use them; `KSpace._fold` brings the pieces into the first Brillouin zone. Build new mesh integrals or contours on them.
  - `kspace._path` builds the k-points, distances and nodes of a path for both `k_path` and `plot_surface_spectral_function`; `high_symmetry_path` supplies standard paths. `band_weights`, `spin_texture` and the fat bands of `plot_bands` share `KSpace._expectations` (one `_eigs` call for several operators).
- **Validation is centralized in `tbkit/error_handling.py`.** Every public method validates its arguments by calling `error_handling.*` checks before doing anything else, and `tests/test_error_handling.py` exercises those paths. Put new argument checks there, not inline. Its `ATOL = 1e-3` is the distance/angle tolerance used throughout `system.py`.

## Conventions

- Sublattice tags are one-character `str` (`'a'`), not bytes (the pre-0.2 API used `b'a'`). The old lowercase class names (`lattice`, `system`, `plot`, `propagation`, `save`) remain as backward-compatible aliases.
- `tbkit/__init__.py` imports classes explicitly, never with `from tbkit.<module> import *`. A wildcard would rebind the `tbkit.lattice` submodule attribute to the alias class of the same name and break `import tbkit.lattice as lattice`. Keep it that way.
- A bug fix gets a pinning test (see `tests/test_regressions.py`) and an entry in `CHANGELOG.md` saying what numbers were wrong and why.
- Gallery examples (`examples/<topic>/plot_*.py`, one topic per folder, each with a `README.rst`) are self-contained and check their key numeric claims with `assert` before plotting. Nothing is claimed in the docs that the code doesn't verify.
- `docs/source/history.rst` is a chronology of Tight-Binding breakthroughs, each linked to the tbkit functionality and to gallery examples via `.. minigallery::`.
  - Every breakthrough links to one or more gallery examples, and no example is linked from two breakthroughs.
  - Each example's title and content must show that breakthrough's subject, so a reader can tell at a glance why it illustrates that entry.
  - Split an example that covers several breakthroughs into focused ones, one per breakthrough, and delete the combined file.
  - When the match is unclear, change the example, not the breakthrough's title or text.
