Coming from Kwant#

If you already write Kwant scripts, this page shows how the same tasks are written in tbkit, where the two codes use different conventions, and one model ported line by line. A model you already have converts in one line, either way, with tbkit.interop:

from tbkit.interop import from_kwant, to_kwant

ham, positions = from_kwant(fsyst, params={'alpha': 0.05})  # finalized Kwant system -> matrix
builder = to_kwant(tr)    # tbkit System or Transport (with its leads) -> kwant.Builder

from_kwant() does not import the leads: attach tbkit leads to the matrix with Transport.

The same tasks side by side#

Task

Kwant 1.5

tbkit

A lattice

lat = kwant.lattice.square(a=1, norbs=1)

lat = tbkit.lattices.square(); any other with Lattice (unit_cell, prim_vec)

syst[(lat(x, y) for x in range(L) for y in range(W))] = 4 * t, or a shape function

lat.get_lattice(n1=L, n2=W), then syst = System(lat) and syst.set_onsite({'a': 4 * t}); shapes with lat.ellipse_in, remove_sites, boundary_line, lat1 + lat2

Hoppings

syst[lat.neighbors()] = -t; lat.neighbors(2) for second neighbours

syst.set_hopping([{'n': 1, 't': -t}]); {'n': 2, ...} for second neighbours, or select by 'ang' and 'tag'

A magnetic field

kwant.kpm

Differences of convention#

  • Hopping values. Both codes store the value you give as the matrix element \(H_{ij}\), with no sign added: Kwant’s tutorial writes \(4t\) on site and \(-t\) for the hopping, and so does the port below. A Kwant hopping value function f(site_i, site_j) gives \(H_{ij}\); a tbkit Peierls phase phase(xi, yi, xj, yj) gives the phase of the same \(H_{ij}\), so a phase written for Kwant carries over unchanged. tbkit adds the conjugate of every bond, as Kwant does.

  • Value functions are vectorized. Kwant calls a value function once per site or bond, with a Site whose position is site.pos. tbkit calls it once per Hamiltonian with arrays: site is a structured array with fields 'x', 'y' (and 'z'), 'tag' and 'index', so write np.where rather than if.

  • Lead order. tr.transmission(energies, lead_in, lead_out) takes the incoming lead first, while SMatrix.transmission(lead_out, lead_in) follows Kwant’s order. Leads are numbered in the order they are attached in both codes.

  • Units. Neither code has units: energies are in the units of the hoppings, lengths in those of the lattice vectors. set_magnetic_field takes the flux density \(B/\Phi_0\), in flux quanta per unit area.

  • No finalization. A tbkit model stays editable after get_ham; call get_ham again after a change.

A quantum wire, ported line by line#

The quantum wire of Kwant’s tutorial (width 10, length 30, \(t = 1\)), with a magnetic field of 0.05 flux quanta per plaquette through the window \(10 \le x \le 20\). The gauge \(\mathbf{A} = (-By\,g(x), 0)\), with \(g\) the window, vanishes in the leads. Without the field, the conductance counts the open channels, 1, 2, 3, 4; with it, Kwant and tbkit agree to \(10^{-12}\) on values that are not quantized.

Kwant (shown, not run when the docs are built):

import numpy as np
import kwant

t, W, L = 1., 10, 30
x0, x1 = 10, 20                      # the field threads 10 <= x <= 20


def window(x):
    return np.where((x >= x0) & (x <= x1), 1., 0.)


def hopping(site_i, site_j, alpha):  # H[i, j], Landau gauge A = (-B y g(x), 0)
    (xi, yi), (xj, yj) = site_i.pos, site_j.pos
    return -t * np.exp(-2j * np.pi * alpha * yi * window((xi + xj) / 2) * (xj - xi))


lat = kwant.lattice.square(a=1, norbs=1)
syst = kwant.Builder()
syst[(lat(x, y) for x in range(L) for y in range(W))] = 4 * t
syst[lat.neighbors()] = hopping

lead = kwant.Builder(kwant.TranslationalSymmetry((-1, 0)))
lead[(lat(0, y) for y in range(W))] = 4 * t
lead[lat.neighbors()] = -t
syst.attach_lead(lead)
syst.attach_lead(lead.reversed())
fsyst = syst.finalized()

energies = [0.25, 0.5, 1.0, 1.5]
G0 = [kwant.smatrix(fsyst, e, params={'alpha': 0.}).transmission(1, 0) for e in energies]
GB = [kwant.smatrix(fsyst, e, params={'alpha': 0.05}).transmission(1, 0) for e in energies]
print('G(B = 0) =', np.round(G0, 13))
print('G(B)     =', np.round(GB, 13).tolist())

tbkit (run, with its assertions, when the docs are built):

import numpy as np

import tbkit.lattices as lattices
from tbkit.kspace import ribbon
from tbkit.system import System
from tbkit.transport import Transport

t, W, L = 1., 10, 30
x0, x1 = 10, 20                      # the field threads 10 <= x <= 20


def window(x):
    return np.where((x >= x0) & (x <= x1), 1., 0.)


def peierls(alpha):                  # phase of H[i, j], gauge A = (-B y g(x), 0)
    return lambda xi, yi, xj, yj: -2 * np.pi * alpha * yi * window((xi + xj) / 2) * (xj - xi)


def wire(alpha):
    lat = lattices.square()          # a = 1, one site 'a' per cell
    lat.get_lattice(n1=L, n2=W)      # sites at x = 0..L-1, y = 0..W-1
    syst = System(lat)
    syst.set_onsite({'a': 4 * t})
    syst.set_hopping([{'n': 1, 't': -t}])
    syst.set_peierls_phase(peierls(alpha))
    syst.get_ham()

    lead = ribbon(lattices.square(), [{'i': 0, 'j': 0, 'R': (1, 0), 't': -t},
                                      {'i': 0, 'j': 0, 'R': (0, 1), 't': -t}],
                  width=W, direction=1, onsite={'a': 4 * t})
    tr = Transport(syst.ham)
    tr.attach_lead(syst, lead, direction=-1)   # lead 0, towards -x
    tr.attach_lead(syst, lead, direction=1)    # lead 1, towards +x
    return tr


energies = [0.25, 0.5, 1.0, 1.5]
G0 = wire(0.).transmission(energies, 0, 1)
GB = wire(0.05).transmission(energies, 0, 1)

# Kwant 1.5: kwant.smatrix(fsyst, e, params=...).transmission(1, 0)
assert np.allclose(G0, [1., 2., 3., 4.], atol=1e-12)
assert np.allclose(GB, [9.4824712e-06, 0.9939437048524, 1.8907644932474, 2.7304048090486],
                   atol=1e-12)
print('G(B = 0) =', np.round(G0, 13))
print('G(B)     =', np.round(GB, 13).tolist())

What tbkit adds, and what it does not do#

The same lattice also gives band topology (Chern and \(\mathbb{Z}_2\) invariants, Wilson loops), Hall, optical and thermoelectric responses, non-Hermitian and Floquet models, crystal symmetry, mean field and exact diagonalization, all on the same System and KSpace objects (see the Tutorial and the example gallery).

tbkit has no Builder: a model is a lattice and its hoppings, not a graph of sites to edit one by one, and from_kwant() imports the finalized matrix, not the Builder with its value functions. Kwant’s time-dependent extension, tkwant, has no tbkit counterpart yet.
